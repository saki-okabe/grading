# 第11回課題（プレ）ガントチャート：採点基準

## 1. 課題と採点の目的

これまで検討してきた大宮祭の出店企画を準備するため、ガントチャートを作成する課題である。

このプレ課題は2点満点とする。ガントチャートの質、正確さ、完成度は採点せず、学生がガントチャートの作成に取り組んだか、取り組んでいないかだけを判定する。

- ガントチャートに取り組んでいる：2点
- ガントチャートに取り組んでいない：0点
- 提出なし：0点

教え合いの記録は採点対象に含めない。教え合いの記載がないこと、不十分であること、具体性がないことを理由に減点しない。

横棒の長さ、開始日、終了日、作業順序、項目数、デザイン、専門的な正確さなどを理由に減点しない。遅れて提出しても減点しない。

PDF以外で提出された場合の扱いはプログラム側で判定するため、VLMは提出画像から元ファイルの形式を推測しない。

## 2. ガントチャートの見分け方

「ガントチャート」という文字が書かれているかどうかだけで判断しない。名称がなくても、次のような表現が確認できれば、ガントチャートへの取り組みがあると判断する。

- 作業、タスク、活動、工程などの項目がある
- 日付、週、月、期間など、時間に関する軸または欄がある
- 横棒、線、色付きセル、記号などで実施期間を表そうとしている
- 作業項目と実施時期の対応を、表または図で表そうとしている

手書き、Excel、Word、表、図など、作成方法の違いは問わない。

未完成、作成途中、項目不足、日付不足、横棒の長さの不備などがあっても、ガントチャートを作ろうとした形跡があれば「取り組んでいる」とする。

反対に、「ガントチャート」という文字だけがあり、ガントチャートを作ろうとした形跡がなければ、取り組みがあるとは判断しない。

## 3. 観察項目

次のすべての項目を、`Yes`、`Partial`、`No`、`判定不能`のいずれかで判定する。

- G1：作業、タスク、活動または工程が記載されている
- G2：日付、週、月、期間など、時間に関する表示がある
- G3：横棒、線、セル、記号などで、作業期間を表そうとしている
- G4：作業項目と実施時期を対応させた表または図がある
- G5：大宮祭の出店企画または企画準備に関係する内容である

## 4. 判定値

- `Yes`：明確に確認できる
- `Partial`：一部だけ確認できる、または作成途中である
- `No`：確認できない
- `判定不能`：見切れ、不鮮明、ページ欠落などにより確認できない

内容の質が低いことを理由に`No`としない。

## 5. 各観察項目の判定

### G1：作業、タスク、活動または工程

- 準備に関する作業、タスク、活動または工程が明確に記載されている：`Yes`
- 作業名の一部だけがある、作成途中である、または項目が極端に少ない：`Partial`
- 作業に相当する項目が確認できない：`No`
- 不鮮明、見切れ、ページ欠落などで確認できない：`判定不能`

項目数の少なさや網羅性の不足を理由に、取り組み自体を否定しない。

### G2：時間に関する表示

- 日付、曜日、週、月、期間など、時間に関する軸または欄が明確にある：`Yes`
- 時間表示の一部だけがある、日付が欠けている、または作成途中である：`Partial`
- 時間に関する表示が確認できない：`No`
- 不鮮明、見切れ、ページ欠落などで確認できない：`判定不能`

開始日や終了日が不足していても、時間を表そうとした形跡があれば`Partial`以上とする。

### G3：作業期間の表現

- 横棒、線、色付きセル、記号などで作業期間を表そうとしている：`Yes`
- 期間表現が一部の作業にしかない、または作成途中である：`Partial`
- 作業期間を表そうとした形跡が確認できない：`No`
- 不鮮明、見切れ、ページ欠落などで確認できない：`判定不能`

横棒の長さ、位置、期間の正確さを評価しない。

### G4：作業項目と実施時期の対応

- 作業項目と実施時期を対応させた表または図がある：`Yes`
- 対応関係を一部だけ確認できる、または表や図が作成途中である：`Partial`
- 作業項目と実施時期の対応が確認できない：`No`
- 不鮮明、見切れ、ページ欠落などで確認できない：`判定不能`

表や図の見た目、整合性、専門的な正確さを評価しない。

### G5：課題との関係

- 大宮祭の出店企画または企画準備に関係する内容である：`Yes`
- 出店企画との関係を一部読み取れるが、対象が曖昧である：`Partial`
- 明らかに課題と無関係な内容しかない：`No`
- 不鮮明、見切れ、ページ欠落などで確認できない：`判定不能`

## 6. 点数の決定

### 2点

次のいずれかに該当し、ガントチャートを作ろうとした形跡が確認できる場合は2点とする。

- G1～G4のうち2項目以上が`Yes`または`Partial`
- 作業項目と期間を対応させようとした表または図がある
- 不完全または作成途中でも、ガントチャートへの取り組みが確認できる

### 0点

次の場合は0点とする。

- ガントチャートへの取り組みが全く確認できない
- 課題と無関係な内容しかない
- 提出がない

G1～G4の機械的な個数だけで、明らかにガントチャートではないものを2点にしない。最終的には、作業項目と実施時期を対応させようとした形跡があるかを確認する。

## 7. 判定不能の処理

画像の見切れや不鮮明さにより、取り組みの有無を判断できない場合は、確認できた範囲で暫定点を出す。

- 確認できた範囲で取り組みが認められる：暫定2点
- 確認できた範囲で取り組みが認められない：暫定0点
- `暫定点`を`true`にする
- `人間確認必要`を`true`にする
- `人間確認理由`に、見切れ、不鮮明、ページ欠落など判定できない理由を具体的に記載する

観察項目に`判定不能`があっても、他の観察項目だけでガントチャートへの取り組みの有無を確定できる場合は、必ずしも暫定点にする必要はない。ただし、`判定不能`によって取り組みの有無を確定できない場合は、必ず`暫定点=true`、`人間確認必要=true`とする。

## 8. 教え合いの扱い

教え合いの記録は、このプレ課題の点数に一切含めない。

- 教え合いの記載がなくても減点しない
- 教え合いの記載が不十分でも減点しない
- 教え合いの記載に具体性がなくても減点しない
- 教え合いに関する観察項目や配点項目を作らない

## 9. 提出形式と遅延

- 遅延提出による減点は行わない
- 提出なしは0点とする
- PDF以外で提出された場合の扱いはプログラム側で判定する
- VLMは提出画像から元ファイルがPDFかどうかを推測しない

プログラム側から提出形式による減点が明示されていない場合、`提出形式減点`は0とする。提出形式の判定はVLMの担当外とし、そのことだけを理由に`暫定点`または`人間確認必要`を`true`にしない。

## 10. フィードバック

ガントチャートへの取り組みが確認できない場合は、不足を簡潔に伝える。内容の質、正確さ、完成度に対する指摘を減点理由にしない。

使用できる例：

- 「ガントチャートへの取り組みが確認できました。」
- 「作業項目と実施時期を対応させた表または図を作成してください。」
- 「作業項目に加えて、日付、週、月、期間などの時間表示を加えてください。」

教え合いの記録について、採点上の不足や減点を示すフィードバックを作成しない。

## 11. JSON出力

説明文やMarkdownのコードブロックを付けず、次の構造のJSONだけを返す。

```json
{
  "点数": 0,
  "暫定点": false,
  "観察項目": {
    "G1": "Yes",
    "G2": "Yes",
    "G3": "Yes",
    "G4": "Yes",
    "G5": "Yes"
  },
  "観点別評価": {
    "ガントチャートへの取り組み": ""
  },
  "配点内訳": {
    "ガントチャートへの取り組み": 0,
    "提出形式減点": 0
  },
  "減点理由": [],
  "評価理由": "",
  "フィードバック": "",
  "人間確認必要": false,
  "人間確認理由": []
}
```

## 12. JSONの制約

- `点数`は0または2とする。
- `ガントチャートへの取り組み`は0または2とする。
- 観察項目にはG1～G5をすべて含める。
- 観察項目の値は`Yes`、`Partial`、`No`、`判定不能`のいずれかとする。
- 教え合いに関する項目を点数計算に含めない。
- 内容の質、正確さ、完成度を点数計算に含めない。
- 判定不能があり、取り組みの有無を確定できない場合は`暫定点=true`とする。
- 判定不能により取り組みの有無を確定できない場合は`人間確認必要=true`とする。
- `人間確認必要=true`の場合は、`人間確認理由`を空配列にしない。
- `評価理由`には、取り組みの有無を判断した根拠を記載する。
- 遅延による減点項目を作らない。
- 提出なしは0点とする。
- VLMは提出画像からファイル形式を推測しない。
- プログラム側から提出形式減点が明示されていない場合、`提出形式減点`は0とする。
- JSON以外の文章をVLMの回答に含めない。
