# 第2回ノート提出（兼 出席届）：採点基準

## 1. 課題の位置づけ

この課題は、ノート提出を出席届として確認するための課題である。提出内容の質は評価せず、提出物が存在するかどうかだけを評価する。

- 1点満点とする。
- 提出物が1件以上存在する場合は1点とする。
- 提出物が存在しない場合は0点とする。
- 遅れて提出されていても減点しない。
- PDF以外の形式でも減点しない。
- 内容の正しさ、分量、文字の読みやすさ、ファイル形式は点数に影響させない。
- 点数は0または1の整数とする。

## 2. 採点方法

この課題は、VLMに答案画像を見せて採点する課題ではない。提出の有無は、`grader.py` の提出物走査処理によって判定する必要がある。

将来的にPython側で、次の順序で処理すること。

1. 対象学生の `第2回ノート提出（兼 出席届）` 課題フォルダを確認する。
2. 対象課題フォルダ内に提出ファイルが1件以上存在するか確認する。
3. 提出ファイルが1件以上存在する場合は1点とする。
4. 提出ファイルが存在しない場合は0点とする。
5. ファイルの拡張子および提出時刻による減点を行わない。
6. 内容確認のための画像変換やVLM API呼び出しを行わない。
7. 共通形式の採点結果JSONをPython側で直接生成する。

提出なしを、VLMに画像を見せて判断させてはならない。提出物が存在する場合も、内容確認やVLM API呼び出しは不要である。

## 3. 観察項目

### S1_提出物が存在する

対象学生の対象課題フォルダに、提出ファイルが1件以上存在する。

- ファイルが1件以上存在する：`Yes`
- ファイルが存在しない：`No`

この項目はVLMではなく、Python側のファイル走査結果から設定する。

遅延提出、PDF形式、提出内容、分量、文字の読みやすさに関する観察項目は作成しない。

## 4. 点数計算

点数は、次の決定木で機械的に計算する。

1. `S1_提出物が存在する` が `Yes` の場合：1点
2. `S1_提出物が存在する` が `No` の場合：0点

`配点内訳` の `提出` は、`点数` と同じ値にする。

| S1_提出物が存在する | 点数 | 配点内訳の提出 |
|---|---:|---:|
| Yes | 1 | 1 |
| No | 0 | 0 |

## 5. 人間確認

空白ファイル、破損して開けないファイル、ファイル走査エラーなどにより、ファイルを有効な提出物として扱えるか判断できない場合は、独自に推測しない。

この場合は次のように処理する。

- `人間確認必要`を`true`にする。
- `人間確認理由`に、対象ファイルと確認が必要な理由を記載する。
- `暫定点`を`true`にする。
- ファイルが存在するという走査結果に基づき、暫定的に1点を入れる。

正常に存在確認できた場合と、提出物が存在しないことを正常に確認できた場合は、`暫定点`と`人間確認必要`をともに`false`にする。

## 6. 出力JSONテンプレート

### 提出物が存在する場合

```json
{
  "点数": 1,
  "暫定点": false,
  "観察項目": {
    "S1_提出物が存在する": "Yes"
  },
  "観点別評価": {
    "提出確認": "提出物が1件以上確認された"
  },
  "配点内訳": {
    "提出": 1
  },
  "減点理由": [],
  "評価理由": "提出物が確認されたため1点",
  "フィードバック": "",
  "人間確認必要": false,
  "人間確認理由": []
}
```

### 提出物が存在しない場合

```json
{
  "点数": 0,
  "暫定点": false,
  "観察項目": {
    "S1_提出物が存在する": "No"
  },
  "観点別評価": {
    "提出確認": "提出物が確認されなかった"
  },
  "配点内訳": {
    "提出": 0
  },
  "減点理由": [],
  "評価理由": "提出物が確認されなかったため0点",
  "フィードバック": "",
  "人間確認必要": false,
  "人間確認理由": []
}
```

## 7. JSONの制約

- `点数`は0または1の整数とする。
- `S1_提出物が存在する`は`Yes`または`No`とする。
- `S1_提出物が存在する`が`Yes`なら、`点数`と`配点内訳`の`提出`をともに1とする。
- `S1_提出物が存在する`が`No`なら、`点数`と`配点内訳`の`提出`をともに0とする。
- 遅延による減点項目を作らない。
- PDF形式の判定項目を作らない。
- 内容に関する評価項目を作らない。
- 通常は`減点理由`を空配列とする。
- `暫定点`と`人間確認必要`は、JSONの真偽値`true`または`false`とし、文字列にしない。
- 提出ファイルが空白、破損、走査不能など、存在判定または提出物としての扱いに問題がある場合だけ、`人間確認必要`を`true`にする。
- `人間確認必要`が`true`の場合は、`人間確認理由`を空配列にしない。
