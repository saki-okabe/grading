# 第2回課題（プレ）目的展開：採点基準

## 1. 課題と採点の目的

この課題では、次の3種類の作業に取り組んだ形跡があるかを評価する。

1. トップダウンアプローチによる目的展開図
2. ボトムアップアプローチによる目的展開図
3. 上記2つを踏まえた最終的な目的展開図

2点満点とする。目的展開図の内容の良し悪し、完成度、見た目、正確性は採点しない。指定された方法を使って作成しようとした形跡だけを判定する。

- 教え合いの記録は採点対象にしない。
- 提出遅延による減点は行わない。
- 同じ不足を複数の項目で重複して減点しない。
- 内容の質を理由に作業点を下げない。
- 学生の意図を推測して加点しない。

## 2. 観察項目で使用できる値

P1～P3は、必ず次のいずれかで判定する。

- `Yes`：該当する作業に取り組んだ形跡が確認できる。
- `No`：該当する作業の形跡が確認できない。
- `判定不能`：ページ不足、不鮮明、見切れなどにより判断できない。

`Partial`は使用しない。

---

## 3. 観察項目

### P1_トップダウン目的展開図への取組

トップダウンアプローチによる目的展開図へ取り組んだ形跡を確認する。

次のいずれかが確認できれば`Yes`とする。

- 「トップダウン」または「トップダウンアプローチ」という見出しがあり、その下に図がある。
- 上位の目的から複数の下位項目へ枝分かれする図がある。
- 「何のために必要か」という上位目的から、「それを実現するために何を行うか」という下位目的または手段へ展開している。
- 最上位の目的を起点に、上から下または中心から外側へ項目が展開されている。

「トップダウン」という文字がなくても、上位目的から下位項目へ展開しようとした図であることが明確なら`Yes`とする。

図の内容、項目数、階層数、矢印の正しさは評価しない。方法を使って作成しようとした形跡があれば`Yes`とする。

- 見出しだけで図や作業内容がない：`No`
- 該当する見出しも図も確認できない：`No`
- 図はあるが、どの方法によるものか判別できない：`判定不能`
- 不鮮明、見切れ、ページ不足により判断できない：`判定不能`

### P2_ボトムアップ目的展開図への取組

ボトムアップアプローチによる目的展開図へ取り組んだ形跡を確認する。

次のいずれかが確認できれば`Yes`とする。

- 「ボトムアップ」または「ボトムアップアプローチ」という見出しがあり、その下に図がある。
- 複数の具体的なアイデア、要求、手段、経験などから、共通する上位項目を導いている。
- 具体的な項目をグループ化し、それらをまとめる目的や意味を上位項目として付けている。
- 複数の下位項目から、上位の目的へ統合される構造がある。

「ボトムアップ」という文字がなくても、複数の具体的項目から上位の目的を導こうとした図であることが明確なら`Yes`とする。

分類方法や導かれた目的の正しさは評価しない。方法を使って作成しようとした形跡があれば`Yes`とする。

- 見出しだけで図や作業内容がない：`No`
- 該当する見出しも図も確認できない：`No`
- 図はあるが、どの方法によるものか判別できない：`判定不能`
- 不鮮明、見切れ、ページ不足により判断できない：`判定不能`

### P3_最終目的展開図への取組

トップダウンとボトムアップで作成した図を踏まえた、最終的な目的展開図へ取り組んだ形跡を確認する。

次のいずれかが確認できれば`Yes`とする。

- 「最終」「最終版」「統合」「修正版」などの見出しが付いた目的展開図がある。
- トップダウンとボトムアップの結果を比較し、整理または統合した別の図がある。
- 前の2つの図とは別に、選択、修正または統合した結果として作られた図がある。
- 最上位目的と、それを展開した下位目的または手段を含む、最終案と読み取れる図がある。

「最終」という文字がなくても、前の2つの図を踏まえて整理した別の図であることが明確なら`Yes`とする。

最終図の完成度や内容の正しさは評価しない。最終案を作成しようとした形跡があれば`Yes`とする。

- 見出しだけで図や作業内容がない：`No`
- 最終案として区別できる図を確認できない：`No`
- 図はあるが、最終案かどうか判別できない：`判定不能`
- 不鮮明、見切れ、ページ不足により判断できない：`判定不能`

---

## 4. 誤判定の防止

- 同じ1つの図を、根拠なくP1、P2、P3のすべてに重複して数えない。
- 見出し、ページ構成、説明文、図の配置を合わせて判断する。
- 3つの図が区別されていれば、それぞれ対応する項目として数える。
- 図の内容が間違っていても、取り組んだ方法が特定できれば`Yes`とする。
- 図はあるが、どの方法によるものか判別できなければ`判定不能`とする。
- 見出しだけで図がなければ`No`とする。
- 不鮮明、見切れ、ページ不足の場合は`判定不能`とする。
- 学生の意図を推測して`Yes`にしない。

---

## 5. 点数計算

AIの観察と点数計算を分ける。最初にP1～P3をすべて判定し、その後で次の手順を適用する。

### 5.1 作業点

P1～P3の`Yes`の個数を数え、作業点を機械的に決定する。

| Yesの個数 | 作業点 |
|---:|---:|
| 3個 | 2点 |
| 1個または2個 | 1点 |
| 0個かつP1～P3がすべてNo | 0点 |

- 提出物がない場合は0点とする。ただし、提出なしの判定はVLMではなく、`grader.py`の提出物走査処理で行う。
- 内容の質、図の完成度、見た目、正確性を理由に作業点を下げない。

### 5.2 判定不能の処理

`判定不能`を`No`として扱わない。

P1～P3に`判定不能`が1つ以上ある場合は、次の順序で処理する。

1. `Yes`と確認できた項目数だけで暫定作業点を計算する。
2. `暫定点`を`true`にする。
3. `人間確認必要`を`true`にする。
4. 判断できなかった項目名と理由を`人間確認理由`に記載する。

`Yes`が0個で、1項目以上が`判定不能`の場合、暫定作業点は0点とする。ただし、人間確認後に点数が上がる可能性があることを`評価理由`に記載する。

例：

- P1=`Yes`、P2=`判定不能`、P3=`No`
- 確認できた`Yes`は1個なので、暫定作業点は1点
- `暫定点`と`人間確認必要`を`true`にする
- 人間確認後に作業点が2点へ変更される可能性がある

### 5.3 PDF形式による減点

提出形式は答案画像からVLMに推測させない。将来的に`grader.py`が、採点対象となった元ファイルの拡張子から判定する。

- PDF形式：`PDF形式減点`は0
- PDF以外：`PDF形式減点`は-1
- 提出なし：最終的な`点数`は0
- 遅延提出：減点なし

この採点基準をVLMだけで使用し、元ファイル形式がプロンプト等で明示されていない場合、VLMは形式を推測せず、`PDF形式減点`を暫定的に0とする。その場合は、形式確認がPython側で必要であることを`人間確認理由`に記載し、`人間確認必要`を`true`にする。形式確認だけが未確定の場合も、`暫定点`を`true`にする。

### 5.4 最終点

次の式で計算する。

```text
点数 = max(0, 作業点 + PDF形式減点)
```

`点数`は0、1、2のいずれかの整数とする。

## 6. フィードバック

内容の良し悪しに対する詳細な評価は行わない。不足している作業またはPDF形式の問題がある場合だけ、簡潔に記載する。

使用できる例：

- 「トップダウン、ボトムアップ、最終版の3種類すべてへの取組が確認できました。」
- 「ボトムアップによる目的展開図への取組が確認できませんでした。」
- 「最終的な目的展開図への取組が確認できませんでした。」
- 「PDF形式で提出してください。」

判定不能の項目について、作業が存在しないと断定しない。内容の正確性、図の完成度、見た目については点数を下げず、フィードバックでも良し悪しを評価しない。

## 7. 出力JSONテンプレート

説明文、前置き、Markdownのコードブロックを付けず、次のキーを一字一句変えずにJSONだけを返すこと。

```json
{
  "点数": 2,
  "暫定点": false,
  "観察項目": {
    "P1_トップダウン目的展開図への取組": "Yes",
    "P2_ボトムアップ目的展開図への取組": "Yes",
    "P3_最終目的展開図への取組": "Yes"
  },
  "観点別評価": {
    "取組状況": "指定された3種類の作業すべてへの取組が確認できる",
    "提出形式": "PDF形式で提出されている"
  },
  "配点内訳": {
    "作業点": 2,
    "PDF形式減点": 0
  },
  "減点理由": [],
  "評価理由": "指定された3種類の作業すべてへの取組が確認されたため、作業点は2点",
  "フィードバック": "",
  "人間確認必要": false,
  "人間確認理由": []
}
```

---

## 8. JSONの制約

- `点数`は0、1、2のいずれかとする。
- `暫定点`はJSONのbooleanである`true`または`false`とし、文字列にしない。
- P1～P3は`Yes`、`No`、`判定不能`のいずれかとする。
- `Partial`は使用しない。
- `作業点`は0、1、2のいずれかとする。
- `PDF形式減点`は0または-1とする。
- `点数`は`max(0, 作業点 + PDF形式減点)`と一致させる。
- P1～P3に`判定不能`が1つでもあれば、`暫定点`を`true`にする。
- P1～P3に`判定不能`が1つでもあれば、`人間確認必要`を`true`にする。
- 元ファイル形式が確定していない場合も、`暫定点`と`人間確認必要`を`true`にする。
- `人間確認必要`が`true`の場合、`人間確認理由`を空配列にしない。
- 同じ不足を重複して減点しない。
- 遅延による減点項目を作らない。
- 教え合いの評価項目を作らない。
- 図の良し悪しを点数へ反映しない。
- 失点またはPDF形式減点がある場合は、該当項目と理由を`減点理由`に記載する。
- `評価理由`には、`Yes`の個数、作業点、PDF形式減点、最終点の計算を記載する。
