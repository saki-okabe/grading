# 第6回ノート提出（兼 出席届）：採点基準

## 1. 課題の位置づけ

この課題は、ノート提出を出席届として確認するための課題である。提出内容の質は評価せず、提出物が存在するかどうかだけを評価する。

- 1点満点とする。
- 提出物が1件以上存在する場合は1点、存在しない場合は0点とする。
- 遅延、PDF以外の形式、内容、分量、正しさ、文字の読みやすさでは減点しない。

## 2. 採点方法

この課題ではVLM APIを呼び出さない。将来的にPython側で、対象学生の `第6回ノート提出（兼 出席届）` 課題フォルダにファイルが1件以上あるかを確認し、共通形式の採点結果JSONを直接生成する。

1. ファイルが1件以上あれば1点とする。
2. ファイルがなければ0点とする。
3. 拡張子および提出時刻では減点しない。
4. 提出なしはVLMではなく、`grader.py`の提出物走査処理で判定する。

## 3. 観察項目と点数

### S1_提出物が存在する

- ファイルが1件以上存在する：`Yes`、1点
- ファイルが存在しない：`No`、0点

空白ファイル、破損して開けないファイル、走査エラーなど、存在の扱いに問題がある場合だけ独自に推測せず、`暫定点=true`、`人間確認必要=true`とし、理由を記載する。ファイルの存在を確認できる場合は暫定的に1点とする。

## 4. 出力JSONテンプレート

```json
{
  "点数": 1,
  "暫定点": false,
  "観察項目": {
    "S1_提出物が存在する": "Yes"
  },
  "観点別評価": {
    "提出確認": "提出物が1件以上確認された"
  },
  "配点内訳": {
    "提出": 1
  },
  "減点理由": [],
  "評価理由": "提出物が確認されたため1点",
  "フィードバック": "",
  "人間確認必要": false,
  "人間確認理由": []
}
```

## 5. JSONの制約

- `点数`は0または1の整数とする。
- `S1_提出物が存在する`は`Yes`または`No`とする。
- `Yes`なら`点数`と`配点内訳.提出`を1、`No`なら両方を0とする。
- 遅延、PDF形式、内容に関する評価項目を作らない。
- 通常は`減点理由`を空配列とする。
- `暫定点`と`人間確認必要`はJSONの真偽値とする。
- `人間確認必要=true`の場合は`人間確認理由`を空配列にしない。
